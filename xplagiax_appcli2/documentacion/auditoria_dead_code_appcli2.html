1 · Executive Summary

appcli2 is a working, actively-developed Flask app with real production hardening (CSP headers, ProxyFix, idempotent startup migrations, session-security config). Its dead code is not random rot — almost all of it has a clean origin story: a route, file, or feature was replaced and the replacement shipped, but the original was never deleted. Three separate cases follow this exact pattern:

  • Auth was rewritten wholesale. auth_routes.py (1,501 lines) was superseded by auth_routes_fixed.py — the import is commented out in app.py:124, so the old file is 100% unreachable, dead weight.
  • Spanish-named pages were rebuilt in English and left behind. /historial, /helpcenter, and /analysis_original are all superseded by /history, (no replacement needed), and /analysiss respectively — and two of the three point at templates that no longer exist on disk, so they'd 500 if anyone ever hit them.
  • MarkTrack / Review Studio / Genuine graduated into separate products. The in-app marktrack.html and genuine.html templates are leftovers from before those became external apps at their own subdomains (confirmed this session — see §3).

The audit also surfaced four broken references in code that is live (a nav link that 500s, two missing CSS files, one missing JS file) — these aren't cleanup candidates, they're bugs worth a ticket regardless of this exercise.

The single largest open question is route-level coverage on the six pure-JSON-API blueprints (x_buck, x_doc, x_integ, x_analysiscounter, x_cleanup, x_system_status) plus the remainder of x_users, auth_bp and billing_bp — roughly 179 routes where blueprint-level "this is called from somewhere" is confirmed but per-route confirmation is not. See Audit Coverage for the honest breakdown before acting on anything not explicitly listed here.

13 · Impact Analysis

Honest framing: this app's dead weight is concentrated in a handful of large files, not spread thin. That makes the win real but modest — this is a hygiene pass, not a performance initiative.

DimensionExpected effect
Project size≈3,650 lines removed from the 7 largest confirmed-dead files alone, plus 7 templates, 12 images, 3 CSS/JS files, 1 dependency pin or two. Meaningful for anyone reading the tree, not a disk-space story.
Import / cold-start timeMarginal. auth_routes.py (1,501 lines) is never imported today since it's commented out — removing the file changes nothing at runtime, only for anyone grepping/reading the codebase.
Request latencyNo measurable effect — none of the confirmed-dead code sits on any live request path by definition.
MemoryNegligible — Flask only loads registered blueprints' modules; the dead ones were never imported, so they were never in memory either.
MaintainabilityThe real payoff. Two fewer "which auth_routes file is the real one?" moments, two fewer 500s waiting to happen if someone relinks a dead route, one fewer place a new hire copies a stale pattern from.
Technical debtRemoves 3 of the 5 duplicate-file/duplicate-function pairs entirely; the other 2 (trial_status/trial_end_modal, the bilingual route naming) need a small follow-up decision, not just a delete.

Methodology

Direct grep -rn/read cross-referencing across the full source tree, run interactively — plus two background research passes (one Python-focused, one static-assets-focused) whose evidence was independently spot-checked before inclusion here. Every route/file/function named above as dead was checked for: url_for() in every template, hardcoded paths in every JS file, redirects from other Python routes, dynamic-construction patterns (f-strings, variable-built paths, JS loaders), and — where applicable — plausible external callers (OAuth providers, payment webhooks). Where a check wasn't completed, that's stated explicitly rather than left implied.
